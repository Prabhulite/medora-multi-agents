# Inpatient admission medication review

For an active admission, authorized staff review every current, reported home medication and record a decision to continue, hold, or stop it for the admission. Hold and stop require a reason. A review of an empty list still requires an explicit attestation. The server locks the admission, patient, and current home medication rows, rejects stale or incomplete decisions, and writes a snapshot and patient audit event in one transaction. If a new home medicine is reported later in the stay, staff can append a decision for exactly the current unreviewed entries. Existing decisions stay unchanged; submitting without new entries is rejected. The initial review time remains the admission review time, while each later item has its own reviewer and time.

The snapshot preserves the medicine, dose, frequency, route, source category and source detail, decision, reason, reviewer ID, and time. It does not create or modify a Medora prescription, change the reported home medication history, or authorize medication administration. A continue decision checks recorded allergies by exact normalized name, but this does not cover synonyms, ingredients, classes, interactions, or dose safety. Staff must verify the reported history against other sources and create any inpatient orders through the clinical prescribing workflow. The historical source and inpatient order are deliberately separate, consistent with [WHO transitions of care guidance](https://www.who.int/docs/default-source/patient-safety/who-uhc-sds-2019-9-eng.pdf).

`GET /api/inpatient/admissions/:id/admission-medication-review` requires `inpatient.view` and `clinical.view`. `POST` to the same path requires `inpatient.view`, `inpatient.update`, and `clinical.view`, with `homeMedicationsReviewed: true` and one `homeMedicationReview` decision per current reported medicine.
