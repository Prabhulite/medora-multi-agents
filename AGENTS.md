# Medora HMS Development Rules

- Inspect before editing.
- Never rebuild the application from scratch.
- Never delete existing modules without approval.
- Never make destructive database changes without approval and backup.
- Use synthetic patient data only.
- Preserve existing APIs and workflows.
- Every task must include tests.
- Work only on the assigned Git branch or worktree.
- Report changed files, database changes, tests, and remaining issues.
- Human approval is required before production deployment.
